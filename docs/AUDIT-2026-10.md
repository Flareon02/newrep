## Root causes

1. **Floating rows while scrolling.** (a) Every price tick replaced the whole `<article>` node (`patchTree`): new
   logo `<img>` decode, lost hover, the scroll anchor node removed — measured: 70 of 80 rows replaced during one
   scroll with updates. Now the row is synced in place (`syncNode`): 0 replaced. (b) `content-visibility:auto` with
   fixed placeholder sizes (400 px per league group, 76 px per History row) — the real size replaced the placeholder
   when a group entered the viewport, and scroll anchoring moved everything on screen. Removed (the DOM is bounded
   already). (c) The ▲/▼ change arrow was inline in a centred price: the number jumped sideways for 20 s; the arrow is
   now drawn outside the number's box. (d) Map scores could wrap and change the row height; now one line.
   The screenshots referenced in the request were not available in this session; these causes were found in code and
   measured in Chromium (layout-shift observer, per-frame offsets inside rows, node identity during updates).
2. **Filters behind other elements / unreachable at small widths.** The toolbar's filter zone and the section tabs were
   horizontal scroll strips with a hidden scrollbar; the filters slid under «Избранное» and the tabs under the status
   buttons. Results/History rows used the wide grid on narrow lists because the base grid rule came after the narrow
   container rule (same specificity). Now everything wraps; audited 8 widths × 7 views: 0 hidden, overlapping or clipped
   controls, no horizontal page scroll.
3. **History 401** — see `server/CHANGELOG-4.16.0.md` (missing `Authorization`, EventSource without `access_token`).
4. **Leagues/links granted but not shown** — `filterForPrincipal` turned the catalog arrays into objects for users
   without `admin.diagnostics`; streams kept stale rights.
5. **Settings not bound to user/key** — single global `prefs`; now user + key profiles synced with the server.
6. **Market grouping by bookmaker wording** — client-side title guessing; Fonbet side-by-sign heuristic. Canonical
   registry v2 on the server.
7. **LIVE thread doing history work** — event history query, cold `COUNT(*)` on `/health`, full re-post of unchanged
   observations to the writer.

## Matching

Checked on the production feeds of 2026-10-06: 21 merged groups with different spellings are all correct aliases
(«1WIN / 1W Team / 1W», «PARIVISION / PVISION», …). Four line fixtures stay separate on purpose: three Valorant
Champions matches listed by Astek and Fonbet exactly 24 h apart (probable date offset at one bookmaker, but a rematch
within a day is possible — the matcher never merges starts > 120 min apart) and a CrossFire pair in different
tournaments. Regression tests: `server/test/matcher-regression.test.js`.

## Known limits

- Market disappearance is not journaled (only status changes): the replay shows a vanished market with its last state
  and its age (`at`); suspended/closed states are exact.
- Fonbet/Astek do not state overtime handling for their generic handicaps/totals → `ot=unspecified` rows are shown
  separately from `included` ones. Confirming the bookmaker rules and adding them to the registry (with a semantics
  version bump) would merge them.
- Pinnacle match-level spread/total of journal rows written before 4.16 have no `bestOf` → unknown (maps vs rounds is
  not provable); new rows carry `bestOf`.
- Astek's plain «Фора/Тотал» at match level (G2/G17, period 0) has no proven unit (separate map and round groups exist)
  → `unit=unspecified`.
