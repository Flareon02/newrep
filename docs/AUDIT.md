# Технический аудит (server 4.3.5 + extension 8.1.2)

Дата: 2026-09-30. Аудит выполнен по исходной точке (`main`, коммит `chore: import original server and extension`).
Метод: чтение кода (server/src ≈ 600 КБ, extension ≈ 350 КБ), grep‑проверки по категориям
риска, запуск сервера локально с пустыми данными (без доступа к букмекерам), прогон
набора тестов (184/184 проходят), проверка поведения API «анонимным клиентом».

Важно: оба проекта написаны плотным стилем (длинные строки, мало комментариев вне
критичных мест) и уже прошли несколько производственных итераций настройки под
1 vCPU / 1 GiB. Поэтому стратегия — **не переписывать**, а точечно исправлять
подтверждённые проблемы отдельными маленькими коммитами.

## 1. Что это за система

```
Chrome extension (MV3, «тонкий клиент»)        Server (Node ≥22, один процесс, Docker)
  background.js  (service worker)   ─HTTP/SSE─►  src/api.js (node:http, без фреймворка)
  app.html/app.js, odds.html, ...                 collectors: AstekBet, Fonbet, GGBET(WS), Pinnacle
  native host (Windows, опц.)                     matcher (worker_threads) → сопоставление матчей
                                                  SQLite (node:sqlite, WAL) + JSON в /data
```

Назначение: агрегатор киберспортивных линий/LIVE/результатов нескольких букмекеров
с сопоставлением матчей между ними, историей коэффициентов, статистикой матчей
(Dota 2, CS2), генератором модельных коэффициентов (HLTV) и связями лиг.

## 2. Подтверждённые находки

Критичность: **H** — исправлять обязательно, **M** — важно, **L** — улучшение.
«Подтверждено» означает, что проверено запуском или прямым чтением кода.

## 3. Что НЕ будем делать (и почему)

- Не меняем язык/фреймворк/БД (Node + SQLite остаются), не вводим микросервисы/очереди.
- Не переписываем `api.js` и остальные модули «ради структуры»: они покрыты 184 тестами и настроены
  под 1 vCPU. Вместо этого выносим новые сквозные механизмы (логгер, ошибки, авторизация) в
  отдельные маленькие модули и подключаем точечно.
- Не меняем схему БД (схема v3 остаётся, миграций нет).
- Не включаем по умолчанию ничего, что удаляет данные или ломает текущее развёртывание.

7. `feat(extension): configurable server URL and token` — по умолчанию прежний адрес.

9. `chore(deploy): lockfile, npm ci, ops scripts` — ротация бэкапов/очистка, `.env.example`.
