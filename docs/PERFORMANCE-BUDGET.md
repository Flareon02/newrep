# Performance budget (1 vCPU · 1 GiB RAM · 10 GB disk)

Принцип: **ничего не выдумываем**. Ниже — только то, что измерено в этой сессии, с условиями замера;
остальное помечено «нужно измерить на сервере» и рядом указано, как.
Все замеры — на изолированной песочнице (не на продакшене), Node 22.22, один процесс сервера,
оригинальные настройки `docker-compose.yml` (`--max-old-space-size=320`, `UV_THREADPOOL_SIZE=2`, `PREMATCH_CONCURRENCY=1`).
Контейнер в этой песочнице не запускался (нет Docker‑демона), поэтому cgroup‑лимит 768 МиБ не применялся — сравнивайте с ним вручную.

## Измеренные значения

| Показатель | Значение | Условия / инструмент |
|---|---|---|
| RAM, холодный старт, пустая БД | **105–115 МиБ RSS** (heap ≈ 13 МиБ) | `node src/index.js`, `/health` |
| RAM, штатная работа | **≈113 МиБ среднее, 136 МиБ пик** за 120 с | `tools/bench-steady-state.mjs`: мок AstekBet из фикстур (12 LIVE‑матчей, 46 лиг), SSE‑клиент + опрос `/api/ui/*` |
| CPU, штатная работа | **≈1,2 % среднее, 3,3 % пик** одного ядра | там же; нижняя оценка — Fonbet/GGBET/Pinnacle не подключены |
| Задержка event loop | максимум 21 мс | `/health` → `runtime.eventLoopMaxMs` в том же прогоне |
| Пик RAM при расчёте коэффициентов (HLTV, 2 команды) | **211 МиБ RSS** (до расчёта 141), 7,4 с | один `POST /api/odds/generate`; воркер с лимитом кучи 256 МиБ; задачи идут по одной (очередь ≤ 3) |
| Загрузка History при старте | **≈1,1 КБ кучи на строку**; 7 снимков × 20 000 строк (140 000) → RSS 272 МиБ, 1,5 с; 1 × 100 000 → RSS 312 МиБ | `tools/bench-history-load.mjs` (до оптимизации загрузки: 296 и 417 МиБ) |
| Предел History при старте | 7 снимков × 40 000 строк (280 000) **не помещаются** в куче 320 МиБ (аварийное завершение) | тот же инструмент |
| SQLite: `COUNT(*)` по 1 000 000 строк журнала коэффициентов | 15 мс (кэшируется на 30 с) | синтетическая БД |
| SQLite: запрос истории одного матча при 1 000 000 строк | 0,4 мс | индекс `(source,event_id,at,seq)` |
| SQLite: размер журнала коэффициентов | ≈215 байт на строку (сжатая запись 153 Б + индексы) → **215 МиБ на 1 000 000 строк** | синтетическая БД, уровень сжатия 1 |
| Логи | ограничены Docker: `local`, **макс. 10 МиБ × 3 файла = 30 МиБ** | `docker-compose.yml` |

## Расчёт бюджета RAM (контейнер 768 МиБ, хост 1 GiB)

| Часть | Верхняя граница | Комментарий |
|---|---|---|
| Основной поток (куча) | 320 МиБ | `--max-old-space-size=320`; фактически 15–150 МиБ, зависит от History (≈1,1 КБ/строка) |
| Воркеры сопоставления | 96 + 112 МиБ | создаются по требованию, завершаются через 10–45 с простоя |
| Воркер расчёта коэффициентов | 256 МиБ | максимум один, только пока пользователь запускает генератор |
| Нативная память, буферы, SQLite (`cache_size` 8 МиБ) | ≈ 50–100 МиБ | WAL‑файл усекается при остановке |

Сумма **лимитов** кучи (320+96+112+256) превышает 768 МиБ: это допустимо, потому что воркеры почти никогда не
работают одновременно и упираются в лимиты только при аномальной нагрузке, но это главный риск OOM. Если контейнер
будет убиваться по памяти (`docker inspect … .State.OOMKilled`), первым делом: (1) уменьшить History
(`HISTORY_MAX`, `HISTORY_TTL_MS`) — см. `/health → runtime.history`; (2) не запускать генератор на LIVE‑пике.

## Что ещё нужно измерить на реальном сервере (не выдумываем)

| Показатель | Как измерить |
|---|---|
| Idle / Normal / Peak RAM с боевыми лентами (все 4 конторы) | `docker stats astek-monitor --no-stream` раз в минуту сутки + `/health → runtime` (RSS, heap, `eventLoopMaxMs`) |
| CPU в LIVE‑пик | `docker stats`, `top -b -n1 -p $(pgrep -f "node src/index.js")`; сравнить с 3,3 % из таблицы |
| Фактический размер History в памяти | `/health → runtime.history` (строки, оценка МиБ, уровень) |
| Рост диска в сутки | `/health → runtime.storage` (`sizeMiB`, `oddsRows`, `freeMiB`) в два момента времени; прогноз = прирост × дни до `freeMiB` |
| Размер логов | `docker inspect --format '{{.LogPath}}' astek-monitor | xargs ls -l` (должен быть ≤ 30 МиБ) |

## Рост диска: что растёт и чем ограничено

| Данные | Ограничение |
|---|---|
| `snapshot_history` (SQLite) | 1 год и 100 000 строк на снимок (`HISTORY_TTL_MS`, `HISTORY_MAX`) |
| `odds_entries_v3`, `odds_state`, `score_entries` | **без ограничения по умолчанию**; `ODDS_RETENTION_DAYS`, `SCORE_RETENTION_DAYS` (0 = хранить всё) |
| `statistics/*.json` | `STATISTICS_RETENTION_DAYS` (0 = хранить всё) |
| Логи | Docker `local`, 30 МиБ |
| Резервные копии, образы, контейнеры | `prune-old-releases.sh` (по умолчанию только показывает) |
| Свободное место | `/health → runtime.storage.diskLevel` (`low` < 1024 МиБ, `critical` < 512 МиБ) + предупреждение в лог раз в час |

## Воспроизведение замеров

```sh
node tools/bench-steady-state.mjs --seconds 120         # RAM/CPU в штатном режиме (нужен server/node_modules)
node tools/bench-history-load.mjs --events 20000        # стоимость History при старте
node tools/compare-with-original.mjs --original main    # ORIGINAL vs NEW
```
